# 多语言设计

状态：0.2 版已实现中文、English、随系统及资源语言包机制。真实会议与桌面验证见 [0.2 版验收记录](second-version-verification.md)。未来原文翻译、在线语言包和 SwiftUI 资源仍属规划。

## 首批语言与选择入口

首批语言选择为「中文」「English」「随系统」，默认「随系统」。中文资源首批为简体中文（zh-Hans），英文为 en；随系统是选择策略（system），不是单独语言包。后续以语言标识扩展繁体中文、日语及其他语言；显示语言自身的名称，不使用国家旗帜代表语言。

首次启动选择「随系统」，按系统语言偏好顺序匹配已支持的语言，无法匹配时使用 English。用户在应用右上角「界面语言」选择三个选项之一，保存选择策略后持续生效；中文和 English 的手动选择不随系统变化。随系统在启动或应用重新进入前台时重新解析，界面可随系统设置变化；新增语言包后也使用同一套匹配规则。地区变体可回退至已有同语种资源，例如 en-GB 使用 en；没有相应文字资源时不能将繁体中文直接标为已有繁体语言包。

创建会议提供「会议输出语言」，同样可选中文、English、随系统，默认沿用当前界面语言的选择策略，可独立选择。随系统在会议开始、形成共同输入版本时解析成具体语言并固定；系统随后变化不改写本场已开始的会议。设置页将两者分开说明：界面语言用于按钮、菜单和状态；会议输出语言用于参会者的新发言、独立报告、对照摘要及总结稿。代码、来源标题、引文和专有名词允许保留原文。

## 保存和切换规则

- 应用偏好保存界面语言选择策略；每场会议保存输出语言选择策略及输入版本里解析后的实际语言。两者分别持久化，重新打开后恢复；进行中的会议使用已固定的实际语言，不再次按当前系统解析。
- 界面语言可随时切换，会议进度、已提交报告及历史正文保持原样。新会议使用新的默认语言，已存在的会议继续使用自身语言。
- 输出语言在独立调查开始时固定到共同输入版本，保证每位接收一致要求；第一版不在执行中的同一批报告里部分修改语言。用户需要改题或改输出语言时，可暂停并选择重新调查，保留旧输入和报告。
- 公开讨论阶段若以后支持更改输出语言，变更在公开回合边界生效，所有后续调用获得同一要求，并记录变更事件；不追溯改写旧发言。首批实现先以新会议或重做调查处理，减少状态复杂度。
- 每次调用清单记录请求输出语言；内容可记录观察到的语言或未知状态，不因提示词要求中文就声称模型实际全部输出为中文。
- 来源和附件保留原始内容、作者和关联关系。用户问题按原文保存；agent 以会议输出语言回应。

## 翻译与溯源

界面语言切换只切换产品文本，不触发模型翻译或额外付费调用。初版可以显示其他语言的原始会议，不要求所有历史记录随设置改变语言。

以后如加入「翻译此发言/报告」，由用户主动请求，译文作为附属内容保存原文编号、来源语言、目标语言、翻译作者或服务、时间及版本。显示「译文」，提供查看原文；翻译失败保留原文，不把译文替换成原作者发言，也不把翻译视为新的证据验证。

决策稿引用稳定的发言与观点编号，不依赖翻译后的措辞作关联。调查报告、总结稿和用户最终决定的语言可以不同，引用仍可追溯。

## 语言包结构

使用稳定、与中文或英文句子无关的文本键，例如 meeting.create、mode.independent、report.submitted、decision.author。各语言包包含语言标识、自称名称、文字方向、资源格式版本和翻译文本。产品文案集中维护，组件中不直接拼接中文或英文。

语言包范围包括导航、表单、状态、按钮、确认操作、错误说明、日期与数量格式、可访问性标签、桌面菜单及引导文字。用户填写的问题、模型正文、原始日志和第三方来源不是静态语言包资源。

动态文案以完整句子及具名参数翻译，例如「{completed}/{total} 份报告已提交」；各语言允许调整参数顺序。数量、复数和日期交由语言资源与格式层处理，不靠字符串连接生成句子。数据库状态和事件使用稳定标识，显示时再映射为当前语言。

缺少翻译时依次使用同语种回退、English，再使用通用可读说明；不把内部键或原始异常作为普通界面文案。开发检查报告缺失键，正式语言选择列表仅展示经过验证、完成必要文本的语言包。

文案维护源与运行时格式分开：未来 SwiftUI 客户端可生成自己的原生本地化资源，现有客户端可生成相应资源文件；协议里的文本键、参数与语言标识保持一致。会议服务保存错误代码和参数，客户端显示对应翻译，原始 provider 错误留在详情和导出材料中。

共同 skill 的证据规范和 JSON 字段语义保持一致；会议语言作为明确的输出要求随每次调用发送，记录所用规范版本。界面翻译不自动修改工具名、协议字段、调用命令或原始日志。

首版语言包随应用交付。新增语言通过资源与构建更新加入，不需要改变会议数据格式或复制一套界面逻辑；在线下载语言包的更新、完整性和兼容性另行设计，不隐含已支持从任意地址安装资源或代码。

## 为更多语言预留的界面规则

- 按钮和卡片允许文字变长，不用固定中文字符数量定义宽度；小屏可换行，关键操作始终可访问。
- 不以左右方向代表业务身份；预留从右到左的排版支持，对照顺序和阅读顺序单独处理。实际开放这类语言前必须做布局验收。
- 日期和时间显示按用户界面语言及所在时区格式化，存储使用统一时间值；轮次、编号和证据关系不受显示格式影响。
- 搜索支持原文；翻译与分词策略后续分别验证，不宣称单一搜索规则覆盖所有语种。

## 验收标准

1. 中文、English、随系统三项选择及重启恢复成功；菜单、错误、状态和可访问性标签随设置切换。默认随系统，未支持语言回退 English；手动选择不受系统变化影响。
2. 使用英文界面创建中文会议、中文界面创建英文会议，各参会者取得同一输出语言要求。
3. 切换界面语言不会重启 agent、重新生成报告、产生翻译调用或改变已有原文与引用。
4. 随系统的界面在系统设置变化后重新匹配，而已开始会议的输出语言保持固定；在途调查不会只有部分参与者获得新语言。重做产生新输入版本，保留原调用与报告。
5. 缺失键、参数、复数、日期、长文案和小屏布局有检查；新增测试语言包无需修改核心组件即可加载。
6. 模型没有遵守语言要求时仍保留真实输出，允许用户要求重试，记录实际情况；不通过未标记的自动改写冒充原输出。
7. 未来译文导出与回看始终保留原文关联；原始 CLI 输出和来源标题不因语言包变化而修改。
