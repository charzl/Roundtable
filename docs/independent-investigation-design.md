# 分开调查模式设计

状态：0.2 版已实现 Mac 上的 Codex / Claude 独立调查核心流程；AGY 全局 MCP 无法按调用隔离，目前仅提供共同讨论。验收见 [0.2 版验收记录](second-version-verification.md)。下文仍包含手机布局、后台研究、数据库迁移等后续方向。



## 目标与模式选择

创建会议时选择「讨论模式」或「分开调查模式」。讨论模式沿用逐个发言、读取共同记录的流程；分开调查模式先形成独立报告，再对比、交叉核查和总结。两种模式都保留真实参会身份、证据链和用户最终决定。

分开调查默认选择三个不同的可用运行时，也允许至少两个。CLI 运行时不同不等于底层模型不同：显示请求模型、实际观察到的模型及未知状态，不暗示已经验证模型多样性。

用户填写问题、背景材料和判断标准，选择参会者、总结人及总轮数（默认 10，允许 1–10）。总结人默认参会列表首位，可更换；开始后模式固定，总结前可以更换总结人并记录变更。

界面与会议输出均可选中文、English、随系统，默认随系统，分别保存。会议开始时解析并固定具体输出语言，独立调查中的所有参会者收到同一要求；语言包、切换和原文保留规则见 [多语言设计](localization-design.md)。这些选择也属于创建会议表单。

## 完整流程

```mermaid
flowchart LR
    A[共同题目与材料] --> B[第 1 轮：并行独立调查]
    B --> C[报告封存与齐备检查]
    C --> D[统一公开，生成对照表]
    D --> E[第 2–10 轮：串行讨论与核查]
    E --> F[指定总结人起草决策稿]
    F --> G[用户选择、要求补证或保留分歧]
```

「最多 10 轮」包含独立调查：调查算第 1 轮，每人提交一份报告；后续最多 9 轮，每轮每位参与者公开发言一次。报告齐备且全员报告中建议总结时可直接起草决策稿；否则继续讨论。开放问题可以留给用户判断，不以全员同意同一个方案为结束条件。

配置为 1 轮时，公开报告后直接总结，界面明确「仅独立调查，未进行交叉讨论」。总结调用作为收尾记录单独显示，不算新的讨论轮；达到上限后不再触发 agent 互相讨论。总结失败的重试也单独记录。

## 独立调查阶段的信息边界

- 每位 agent 收到同一版本的问题、用户材料、判断标准及明确指定的既有公开参考资料。记录输入版本和哈希；不自动读取其他会议或历史调查报告。
- 共同 MCP 配置及 skill 统一维护并固定版本。独立阶段的 skill 明确要求基于自己的调查提交；公开讨论阶段再要求复用和核查同伴研究，替代现有规范中无条件「复用共享研究」的表述。
- 内置会议 MCP 按会议、阶段、参与者和调用授权。独立阶段只能读取共同基础材料、自己的研究与报告；不能读取同伴报告、草稿、核查或原始输出。提示词和客户端事件接口也使用相同的可见性规则。
- 每位 agent 使用自己的工作目录及附件范围。开发时要分别验证各运行时能否限制原生文件工具的读取范围；只有提示词和 MCP 过滤不能证明操作系统级隔离。
- 外部 MCP 按实际能力显示。只读资料查询可共用配置；可检索本次同伴产物或共享可变记忆的工具，需要参与者隔离的命名空间或在此阶段禁用。私有草稿不写入公开工具、共同文件或共享记忆。
- 三方可读取同一外部来源，这不是违规。动态网页可能在不同时间变化，各自记录访问时间及实际取得的资料，不能声称外部查询结果完全一致。
- 本阶段界面只展示状态和取得输出的证据，不实时展示结论正文。有效报告封存后，提供「已提交，待统一公开」。齐备前暂不提供单份预览，保持统一公开的交互规则。

当前 AGY 的共享 MCP 适配尚未验证，全局工具配置不能按调用隔离，因此本版不开放 AGY 独立调查。Codex / Claude 的独立阶段禁用外部共享 MCP，Mac 文件限制保护本项目数据树；远程服务及运行时外部缓存不在此次隔离验证范围。不能显示为已完成网络调查，除非有实际查询与结果证据。

## 独立报告的统一结构

| 字段 | 要求 |
|---|---|
| 建议结论 | 推荐方案及关键理由；允许没有足够材料给出建议 |
| 关键观点 | 区分事实、推断、建议，分别建立稳定编号 |
| 证据与研究 | 来源、必要输入、分析或实验方法、实际结果及关联附件 |
| 备选方案 | 优点、代价、适用条件；不强制每位 agent 给出不同答案 |
| 假设和局限 | 判断依赖的条件、未核实事项及缺失能力 |
| 后续问题 | 需要其他参会者或用户回答的问题 |
| 总结准备情况 | 是否建议进入总结及其理由，不代表事实已获验证 |

公开时将每份报告转换为带真实作者的第 1 轮公开发言，并链接完整报告。正文不可自动改写成另一个参会者的语气。来源缺失可以作为局限公开，标记「缺少依据」，不伪造来源，也不把分析计划当作执行结果。

有效提交需要真实调用完成证据、身份对应及结构校验。进程启动、工具初始化、出现部分文字分别记录，不能据此直接标为「正在研究」或「报告完成」。

## 统一公开与对照

所有参与者有有效报告后，通过一次持久化提交开放这一批报告，并串行编号为公开发言；发布顺序按既定参会列表，不按完成速度。公开后所有 agent 取得同一份完整材料；后一位的独立报告不因公开顺序而重新生成。恢复或重试不能重复发布。

对照区显示每位的原始建议、关键依据、假设和未解决问题。初版直接引用报告字段排列，不自动宣布「多数正确」或「已达成共识」。语义上的一致与冲突由后续讨论记录支撑；如加入模型生成的差异摘要，标为具名作者的草稿并保留引用。

报告区布局：Mac/iPad 宽窗口可三列对照，iPhone 使用参会者切换或纵向卡片。所有布局使用同一份会议数据，原始报告、后续修正和决策稿分别可回看。

## 公开讨论与收敛

第 2 轮开始，每位依次读取三份报告及已公开讨论，优先指出影响决策的事实冲突、不同假设或证据缺口。无需指定固定的反对者，也不以产生反驳数量作为任务目标。

每条核查说明具体对象、方法、实际结果和局限。支持、反对、证据不足分别记录；撤回或修改观点建立新版本和关系，不覆盖原文。进一步研究可以认领任务；其结果一旦公开，后续参与者可复用。

每个完整轮次后检查是否进入总结：所有当前参会者都建议总结，且本轮之后没有尚未回应的用户补充；允许保留可交给用户判断的问题。到轮数上限或用户点击「结束并总结」则整理当前实际材料，不延长讨论。

独立调查支持并行调用；公开发言和公开研究成果的发布仍由会议服务顺序提交。本设计的首个实现范围不要求在公开讨论时同时启动额外后台研究任务，该能力继续单独规划。

## 指定总结人和最终决定

总结人读取原始报告、全部公开发言、研究、核查和修正记录，生成：

1. 推荐方案与适用条件，或材料不足的明确说明。
2. 各方案的优点、代价和风险。
3. 获得支持的部分及仍存在的异议，保留作者身份。
4. 尚待验证的问题、可能改变建议的条件。
5. 对观点、发言、证据和核查的有效引用。

标题显示「由 X 整理的决策稿」。总结人的观点保留为作者判断，不自动赋予全体同意或已验证状态。首次总结不隐含额外研究权限；若提出新的关键事实，标为待验证，并由用户决定是否另开补充调查。

用户可记录自己的决定和理由。最终决定与 agent 决策稿分别保存；提出修订后生成新稿，保留旧版本。以后若加入 agent 对总结稿的复核，应占用剩余讨论轮次，不在第 10 轮之后无限增加确认回合。

总结失败时提供「重试总结」「更换总结人」「查看并导出已有记录」。更换明确记录，不悄悄由另一个模型代替。用户提前结束而总结人没有完成独立报告时，其只基于已取得材料起草，并显示缺席和不完整状态。

## 状态、超时与用户控制

会议阶段与暂停状态分开保存：准备、独立调查、等待齐备、公开对照、讨论、总结、结束；暂停时保留具体阶段和进度。参与者状态区分待调用、进程启动、收到输出、有效报告封存、格式失败、调用失败、超时、中断及用户跳过。

调查超时设置在高级选项中，建议初始产品默认每次调用 10 分钟；0.2 版已使用该独立调查预算，可设置 1–30 分钟；共同讨论仍采用每次调用 180 秒。预算和时长均显示；默认不自动重试，用户重试需保留原失败尝试，额外消耗另计。

| 情况 | 行为 |
|---|---|
| 某位失败、超时或格式无效 | 其他在途调查可完成并封存；停在齐备检查，用户选择重试该位、明确跳过或结束 |
| 跳过参与者 | 保留其身份与失败原因；至少两份有效报告才进入完整对比讨论；不足两份时可交付明确标记的部分材料总结 |
| 暂停独立调查 | 停止调度新任务并取消在途调用；已封存的保留，中断的明确记录，继续时仅重新调用缺少有效报告的参与者 |
| 调查期间用户补充 | 默认排队，报告统一公开后先发布补充，再供讨论回应；不会只发给尚未完成的一位 |
| 用户需立即改变题目 | 选择「按新题目重新调查」，停止在途调用，创建新输入版本并让所有参与者重新调查；旧报告保留但不混入同一批对照 |
| 用户提前结束 | 取消在途调用，公开已封存报告及未完成名单，基于已有材料总结；没有有效报告则仅交付现有记录 |
| 应用重启或崩溃 | 在途调用标为中断，暂停恢复；不自动再次花费额度或把中断计为完成 |

任何重试不增加讨论轮数，但增加真实调用次数、用时和费用记录。运行期间的题目重做也明确标记为同一轮的新调查版本，不能用重试或改题隐藏成本或自动循环。

## 界面草案

创建会议：问题与背景 → 模式选择 → 参会者 → 总结人 → 总轮数 → 会议输出语言。模式下方用一句话说明「先独立提交，再公开对比讨论」；技术性的隔离配置留在共享能力及高级设置中。界面语言放在应用设置中，切换不改写已保存的报告。

调查中：顶部显示「第 1 轮 · 独立调查 · 2/3 已有效提交」；每位卡片显示实际状态、能力范围、已用时间和最近事件，不显示尚未公开的结论。用户可以暂停或结束；失败卡片提供重试及明确跳过操作。

齐备后：显示「独立报告」对照页，会议时间线记录批次公开事件；切换「公开讨论」「观点与证据」「决策稿」。之后讨论默认自动推进，暂停时仍可查看完整报告。

结束：显示总结作者、结束原因、材料是否完整、各方案与引用；用户可以记录决定、导出，或以明确选择的公开材料创建补充会议。

## 存储与实现边界

建议为会议增加 mode、phase、输入版本、总结人、参与者当前有效集合及暂停状态；为报告记录作者、输入版本、提交状态、公开批次、真实调用与附件关系。研究产物与文件均带可见范围和阶段信息；对话、观点修正、总结版本、用户决定及公开事件分别保存。

采用 SQLite 时使用事务保证批次公开与编号一致，使用稳定 UUID 和独立的会议内顺序号；关系和数据类型明确，为以后 PostgreSQL 迁移留出存储接口。当前 JSON 存储可先承载同样的领域模型，数据库迁移不是实现信息隔离的替代品。客户端通过会议服务读写，不能绕过它读取私有结果。

实现顺序建议：阶段与隔离授权 → 并行真实运行时调度和封存 → 批次公开与对照 → 串行讨论衔接 → 总结人设置 → 恢复与迁移。SwiftUI 客户端可复用此协议与产品流程，本文没有启动原生界面或数据库迁移。

## 验收标准

- 用至少两个真实运行时验证并行调查与后续相互回应；三个实际运行时另行验证，不使用一位 provider 模拟三位。模拟测试只能证明调度和权限逻辑。
- 任一报告完成得更早，都不能通过提示词、MCP、客户端接口或可访问的文件读取尚未公开的同伴内容。记录运行时原生工具隔离的实际能力与未解决限制；存在已知泄露路径时，不宣称已实现严格独立调查。
- 同一输入版本的基础材料一致；新题目不会只更新部分参与者。公开重试不重复发言或编号。
- 三份报告公开后，下一位收到完整报告和来源；观点修正能追溯到原报告，总结引用有效且保留异议。
- 两种模式均不突破总轮数；失败与跳过不计为同意；1 轮配置明确没有交叉讨论。
- 崩溃恢复不丢已提交报告，不把中断标为完成，不自动重启付费调用；总结失败和更换作者保留记录。
- 导出包含所选择的会议材料、真实调用和失败证据，排除凭据；私有数据是否导出由用户明确选择，不因普通公开记录接口而泄露。
