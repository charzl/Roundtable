# 产品需求与讨论交接

## 已确认的用户意图

- 应用名称：圆桌会议（Roundtable）。
- 第一版为 macOS 桌面应用，先在 Mac mini 上运行；之后提供手机 App。
- 用户在统一的会议窗口提出问题，Claude、Codex、AGY 等参会者都能看到。
- 参会者能看到其他参会者的公开发言，互相回应、提问和反驳，模拟真实会议。
- 支持持续讨论，不限于多个模型各回答一次。
- 提供两种模式：逐轮共同讨论，以及同题并行独立调查、统一公开后对比讨论。独立调查算第 1 轮，总轮数仍最多 10；创建会议时选择 Leader（会议负责人），Leader 在结束时汇总所有参会者意见，负责最后的 summary。详细规则见 [分开调查模式设计](independent-investigation-design.md)，核心流程已实现，验收见下文。
- 语言可选中文、English、随系统，默认随系统，并预留更多语言包。界面语言与会议输出语言分别设置，会议开始时固定实际输出语言；切换保留原始发言与证据。详细规则见 [多语言设计](localization-design.md)，核心流程已实现，验收见下文。
- 同一时间只有一位人类或 agent 公开发言；agent 可以并行研究和分析，再将公开结果带回会议。
- 最多讨论 10 轮，能形成可供用户判断的结果时可以提前结束；到上限必须交付有依据的折中方案，或 pros and cons 与剩余分歧，由用户决定，不自动延长。
- 各方关键观点有迹可查，保留来源、分析方法、必要输入、研究产物、验证结果和修正记录；总结也应引用这些依据并保留异议。
- MCP 配置和 skills 尽量统一维护与共享；共享目录不等于已加载或可调用，各运行时的实际能力和授权仍需验证。研究成果应能复用与交叉核查。
- 自行开发的代码选择 Apache License 2.0；它允许商业使用与闭源衍生，并非逐次授权使用的许可。复用代码保留原许可和版权声明。
- 独立于 BabyLog 开发；原 BabyLog 会话继续讨论 BabyLog。

## 概念边界

模型负责推理和生成回答。Agent 是使用模型的参会者运行时，具有身份、角色、上下文和可选工具。Claude Code、Codex、AGY 是潜在的接入入口；具体模型与可用接口需核实当前配置和官方文档。

圆桌会议负责公共会议记录、消息分发、发言调度、参与者状态和用户控制。不要假定这些入口自动共享当前聊天或彼此上下文。

## 第一版建议，尚待在新项目讨论

- 本地会议服务与界面分开，为以后手机接入保留接口。
- 公共会议记录保存人类和各 agent 的公开发言，保留身份与时间。
- 先独立发言，再围绕彼此观点讨论；用户随时插话、暂停、点名或结束。
- 自由讨论允许自主选择回应对象；发言调度有轮次、并发和费用上限，避免无限相互触发。
- 显示真实连接状态，包括未登录、等待授权、运行中和失败；演示数据与真实模型输出明确区分。
- 会议记录可回看，结论区分共识、分歧与待验证事项。
- 初期工具权限以讨论为主，写文件、运行代码等能力单独设计。

macOS 桌面产品形态已确认。用户授权开始开发后，第一版采用 Electron 界面、独立 Node.js 本地会议服务和真实 CLI 适配器。默认使用本机已有登录；模型可在创建会议时指定，费用依参会者账号。API 接入、手机界面与远程认证仍待设计。

## 现有方案借鉴与桌面设计方向

- 用户倾向借鉴同名开源项目 [ai-us-stock-lab/roundtable](https://github.com/ai-us-stock-lab/roundtable)。静态评估认为它适合作为第一候选，尚未决定导入哪些代码。
- 已核查 v0.4.2（提交 `ec07e195e802d52a6754a09eac8fda21c70143f7`）的部分源码与 MIT 许可证。可参考或按许可复用 agent 调用、记录、串行讨论和决策展示；上游代码、许可证与版权声明应保留适当来源记录。
- 桌面应用应管理本地会议服务的启动、状态和退出，并提供独立窗口、会议记录与共享能力入口。未来手机连接同一个会议服务，避免把讨论逻辑直接绑定在桌面窗口内。
- 桌面打包不会自动解决真实接入、共享 MCP、证据验证或收敛规则；这些缺口仍需实现与验证。
- 详细静态评估见 [现有方案复用评估](solution-reuse-assessment.md)。本次没有运行上游应用或启动参会 agent。

## 早期接入试验的证据（历史）

在 Orca 中尝试了 Claude 与 AGY 的只读讨论，但没有获得可验证的讨论结果。Claude 启动停在工作区信任提示，其失败 worker 已释放；AGY 的输入被接收，但未验证回合开始，也没有取得报告。不得将这个早期试验描述为已经实现跨模型会议。后续第一版的成功证据在下一节单独记录。

## 第一版实现与后续验证

用户于本会话授权开始工作，并允许需要时调用 Antigravity；开发和验收由主 agent 负责。

- 已实现桌面窗口、本地会议服务、公共记录与回放、逐个公开发言、排队插话、暂停与结束、最多 10 轮、全员本轮建议总结时提前结束，以及带观点编号的决策稿。
- 提供 Codex、Claude、AGY 的真实 CLI 适配。失败、格式不合要求及退出中断分别保留，不将进程启动等同于模型完成。真实输出和原始调用材料均保存。
- 内置共享 MCP 支持公开记录、研究产物与观点核查。规范随每次调用提供；会议固定配置版本，调用清单保留哈希。外部 MCP 配置统一维护，再适配运行时格式。
- 已验证 Codex / Claude 读取同一会议 MCP、相互回应和核查；三运行时会议中 AGY 在格式解析失败后重试成功，记录保留失败。不能据此声称 AGY 的共享 MCP 或三个不同底层模型均已验证。
- 0.1 版最终稿由首位已成功发言的参会者起草；0.2 版支持用户指定和更换总结人，由所选参会者起草，明确标为草稿，保留异议和未知项；不是主持服务认证的共识。总结失败时仅呈现已有记录，明确失败，不伪造优缺点或结论。
- 0.2 版已提供 Codex / Claude 并行独立调查；公开讨论中的额外后台研究任务调度尚未实现。手机 App、远程接入、外部 MCP 的具体连接与权限，以及更长会议的上下文处理仍待验证。
- 验收证据与限制见 [第一版验收记录](first-version-verification.md)。

## 0.2 版实现与验证

- 两种会议模式、可指定总结人、并行报告封存与统一公开、后续串行讨论、单独失败重试/跳过、调查输入版本、总结与用户决定历史均已实现。
- Codex / Claude 真实调查调用时间重叠，输入哈希相同，两份报告后完成第 2 轮相互回应及 Claude 决策稿；失败调用另行保留。AGY 的原生文件读取限制已试验，但全局 MCP 不能按调用限定，0.2 初次验收因此只开放共同讨论；用户随后明确要求优先取得 AGY 的意见，0.2.1 已开放 AGY 独立调查，共享 MCP 适配继续单独完善。
- 中文、English、随系统已实现，界面语言与冻结的会议输出语言分离；语言包集中维护，切换不改写原文或触发模型调用。
- 修正旧版打包识别和包内数据目录问题。桌面数据统一存于 `~/Library/Application Support/Roundtable/data/`，旧记录复制迁移，冲突版本保留。曾有一场仍运行的旧会议被重建安装包删除原始文件；已恢复公开记录、稿件和调用状态，但其原始调用附件未恢复，界面与验收记录明确说明。
- 使用 JSON 存储，未迁移 SQLite，也未开始 SwiftUI 或手机 App。详细证据与范围见 [0.2 版验收记录](second-version-verification.md)。

## 0.2.1 调整

用户明确会议须选出一位 Leader，并由该 Leader 负责最后的 summary。创建、参会者身份、会议中变更和总结调用统一使用 Leader；旧版 summarizer 数据兼容读取，原稿作者和记录不改写。Leader 的总结包含各方观点、依据、优缺点、异议和未知项，最终决定由用户保存。

用户接受当前工具限制，要求 AGY 同样参加独立调查，优先取得其意见。已移除工具隔离未验证导致的参会禁用，保留已验证的文件限制、报告封存和分批公开。AGY 使用提示词里的同题材料，不能据此声称项目共享 MCP 已接通。其全局 MCP 范围继续另行适配。
