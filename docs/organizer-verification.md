# Organizer 与会后追问：开发代码验收

## 已确认的角色规则

Organizer 与 Leader 分别选择。新会议默认 Cursor 做 Organizer，候选还包括 Codex、Claude、AGY；也可不使用 Organizer，沿用固定顺序。Organizer 不参加本场独立调查或讨论，不提交额外观点，不负责最终总结。Leader 必须是本场参会者，由用户选择并负责最终 summary。当前 Cursor 只提供 Organizer 接入，不是研究参会者选项。

界面在选择 Organizer 后取消该运行时的参会勾选并更新 Leader 候选，服务端拒绝角色重叠。已有会议允许选择非参会运行时担任 Organizer，不静默移除或改写原参会者。旧记录缺少 Organizer 时保持为空，避免升级后自动增加真实调用。

## 调度及追问

每轮最多一次 Organizer 安排，返回本轮剩余参会者的完整排列，程序验证身份、重复、遗漏及实际公开引用。暂停后保存顺序，切换或关闭 Organizer 不重复已完成的发言。独立报告封存时不调用 Organizer；报告公开后的讨论才提供报告材料。轮数上限、逐个公开发言及全员提前结束规则仍由程序执行。

会后追问单独保存问题、回答者、所依据的总结版本、用户决定、分配理由、公开引用和调用尝试。自动分配仅选择具有原会议公开发言的参会者；点名或引用原文跳过路由调用。含糊问题等待用户选人，无效引用不触发回答者。取消、失败和退出中断保留状态并要求手动重试；重试可明确换人。原会议轮数、公开讨论和总结不自动覆盖。

调用记录明确保存实际运行时、任务角色和模型元数据。项目 MCP 不注入 Organizer；公开记录及共同规范随提示词提供。Claude Organizer 关闭内置工具，Cursor 使用 ask 模式及项目工具拒绝配置。AGY 的全局工具范围仍未按本项目隔离，不能声称所有 Organizer 运行时均已隔离或接通共享 MCP。

## 验证证据及限制

- `npm run check`：源码语法检查。
- `npm test`：角色选择、默认 Cursor、角色互斥、Leader 总结、独立报告不含 Organizer、轮数上限、引用校验、追问上下文、澄清、暂停恢复、取消、旧记录兼容及 HTTP 身份校验。模型答案全部使用明确的 fixture，不是实际模型接入证据。
- `npm run smoke:desktop`：实际 Electron 窗口，新建对话框中切换 Organizer 自动排除对应参会者及 Leader 候选，默认 Cursor，保存及重开保留角色；零真实模型调用。
- `npm run smoke:organizer`：独立测试服务与 Electron 窗口，验证自动分配、手动选人、含糊问题等待选择、原文追问、语言切换保留草稿、保留总结及重新打开页面后回看。所有标题、发言和模型名明确标注 fixture。结果保存在被 Git 忽略的 `output/verification/organizer-desktop/result.json` 与截图。
- 当前本机 `cursor-agent status` 返回 `Not logged in`。只确认 CLI 已安装；未取得真实 Cursor 模型主持或分配结果。其他运行时新增的 Organizer 角色亦未进行真实模型验收。不得把测试适配器结果算作多个真实 agent 成功协作，也不承诺免费额度。

开发阶段验证使用本仓库的开发窗口及隔离数据，不替换另一工作区正在运行的安装包。运行中的旧桌面实例不会自动加载源码变更。

## 0.3.1 持续对话与回答语言

用户要求取消独立 follow-up 页面，Discussion 现在使用同一个输入框提交讨论发言和总结后的新问题；后续问答追加在原公开记录下方。自动分配、点名、澄清、取消和重试保留，但不要求切换页面。已有会后问答继续回看，原总结与轮数不自动改变。

默认回答语言改为「用提问者的语言回答」，与界面和系统语言分开；旧版随系统会议的新调用也按当前问题回应。公开讨论、同批独立报告、Organizer 的说明、Leader 总结及新问题回答均取得相应规则。明确要求另一种语言时优先遵守，JSON 字段、编号和原始引文保留。每次调用记录语言策略和关联问题；提示词要求不等于模型已实际遵守语言。

49 项测试通过，包括英文系统上中文问题的各阶段语言规则、连续中英文问题、明确语言选择及旧数据兼容。开发桌面和隔离 Organizer 窗口验证了统一输入框、没有 follow-up 标签页、原总结保留、连续提问、语言切换保留草稿和重新打开回看。验收使用 fixture，未新增真实模型调用。
